## 4. 一致性验证（最高风险项的方法）

**问题**：重写战斗表现与预测和解时，最容易出的是"看起来一样、判定不一样"。

**方法**：输入序列 + 初始状态 + `SimStep` → 状态摘要对拍。

```
旧客户端（或测试夹具）录制一局：SimInputFrame[]（含帧号、视角、移动、开火、换弹）
        ↓ 存为 Tests/Fixtures/match_{1,2,3}.bin
新工程 Tests/ParityTests.cs：
        var sim = new SimWorld(fixture.InitialState);
        foreach (var f in fixture.Inputs) { sim.Step(f); digest.Add(sim.Digest()); }
        Assert.Equal(fixture.ExpectedDigests, digest);        // 全量 + 公共两个口径
```

- 摘要口径：沿用 `com.litegame.sim` 现成的全量/公共摘要，**不新造**。
- 对拍覆盖：开局 3 s、命中/死亡、复活、结算四个区间各一局；**P1 第一天就建立**，而不是收尾时补。
- `LocalPredictor` 的验证点不是渲染，而是"重放后 digest 与直接步进一致"（预测正确性），以及"回滚到快照帧再重放"的幂等性。

## 7. 双工程并行期规则（P0–P3 适用）

**旧仓角色收敛**：只承担四件事——① 服务端（RoomServer/MetaServer）；② 共享包（sim/net/sync）；③ Luban 表源；④ 云侧部署脚本。旧客户端只修 bug，不加功能。

**四条同步规则**

1. **协议/判定变更**：只在旧仓改包 → `toolbox.py build-hash` → 新工程 `file:` 引用自动跟随 → 两端同批发版。
2. **配置表变更**：只在旧仓 `Luban/` 改源 → 生成 → 新工程 `python Tools/sync_shared.py` → `verify.py` 校验哈希。
3. **新客户端改动不回流**（除紧急线上 bug）：避免两套客户端互相污染。
4. **BuildHash 一致**：新客户端不重算、不改包内常量；`verify.py` 每次跑都校验 `BuildHash.Value` 与包源哈希匹配。

**切换判据（P4 之后）**
- 旧客户端连续 2 周无线上新增问题；新客户端连续 3 局联机无回归；→ 拷贝包快照（02 §6.1 方案 B）、旧客户端入口下线、旧仓删除客户端 UI 工具链与业务层（保留服务端与包）。

**回退预案**：任一阶段卡住超过预期两倍，暂停"删旧"、把当前阶段降级为"可用即可"，先保证有一个能跑的客户端，再回来收口。

## 8. 可选演进：HybridCLR（不在 P0–P4 内）

**性质**：可选，不阻塞 P0–P4。P0 已把边界缝做出来（`BootEntry`/`IGame`），所以接入是"装包 + 改 asmdef + 加装载"，不是重构。

**触发条件（三条同时满足才做）**

1. 出现"必须不改安装包就修 C# 逻辑"的真实需求（渠道审核、线上事故、外包交付）；
2. 该需求频率 ≥ 2 次/月，且 Lua + 资源热更覆盖不了；
3. 能承担 +1 出包步骤、+100~300 ms 启动、调试链路变复杂。

**前置**（01 §15 的 H1–H4 ＋ P0 交付的 `Core/Host/{BootEntry,IGame}` 与 `Game/Boot/GameBootstrap`）。

**接入步骤**（量级参考 ≈3 人日）

1. 装 HybridCLR（版本对齐 2022.3.55f1c1）→ `Generate/All` → 写 `link.xml` 白名单（AOT 面只有 Core 八件，规模可控）。
2. `LiteGame.Game.asmdef` 改为热更程序集（编译产物变成 dll，不再进 AOT 程序集列表）。
3. 启动序列插入装载：`Patch` 段下载 `Code` 组 → 摘要校验（复用 `AssetHost`）→ `Assembly.Load` → `GameBootstrap.Register()` → `BootEntry.Create`。
4. 打包流水线加 `Code` 组，与 Main/Config/Lua 共用**一套**内容清单与摘要（不另建第二套）。
5. 装载在首帧前完成（Loading 遮罩），失败则拒绝启动新版本、保留旧 dll。

**退出条件**

- [ ] 改一行 C# 逻辑 → 出热更包 → 不重装客户端生效
- [ ] 二次启动 ≤ 300 ms，首启不回归
- [ ] AOT 面零改动（除 `GameBootstrap` 调用点）
- [ ] `verify.py` 增一条：热更 dll 的 BuildHash 与 AOT 内 `BuildHash.Value` 一致（版本闸门，不一致拒绝装载）

**回退**：asmdef 改回普通程序集 + 删装载步骤 = 1 小时内退回 P4 形态。

| 风险 | 对策 |
|---|---|
| dll 与 AOT 接口不一致（改了接口没重编译） | BuildHash 当闸门：不一致拒绝装载并保留旧 dll，日志一次 |
| 与 YooAsset 清单冲突（两套版本） | `Code` 组与 Lua 组共用同一清单，禁止另建 |
| 裁剪删掉被热更调用的 AOT 方法 | P0 起维护 `link.xml` 白名单；AOT 面小是这项可行的前提 |
| 泛型值类型缺元数据 | 热更侧集合优先用引用类型，struct 登记进补充元数据清单（01 §15.3） |
